    System overview

    The Nexus console is an open source software framework to operate PCIe measurement cards from Spectrum Instrumentation in a high performance computer system. Pulse sequences are defined in the open Pulseq format [2], converted directly into sampled waveforms on the host computer and streamed to the transmit card. Receive data are recorded in a gated mode, processed on the host and exported in the ISMRMRD format [4]. The figure follows the path from the user through the software on the host computer down to the hardware.

    Interfaces

    The nexus console builds on the following interfaces which can be understood as the input and output of the system.

    Interface Description Reference
    Pulseq Open, vendor-independent sequence format. Sequences are created with (Py-)Pulseq and passed to the console as a PyPulseq Sequence object or a .seq file. Pulseq, PyPulseq, Examples
    ISMRMRD Open data format for raw MRI data which allows to streamline the image reconstruction with external frameworks like MRpro. ISMRMRD, MRpro

    Software

    The table gives and overview of the most important software modules implemented within the Nexus console.

    Component Description Reference
    AcquisitionControlManager A Python multiprocessing manager which provides a service that can be started with the nexus command. It serves a single AcquisitionControl instance such that clients receive a proxy that behaves like a local AcquisitionControl. Acquisition service, Service deployment
    AcquisitionControl Loads the device configuration, creates the sequence provider, both cards and the processing pool. It controls the sequence calculation and execution. Acquisition
    NexusConfiguration Static description of all the relevant parameters of the setup which are needed to calculate and execute a sequence correctly. Device configuration
    AcquisitionParameter Runtime parameters of an acquisition, e.g. Larmor frequency, gradient offsets, etc. Acquisition
    SequenceProvider Subclass of the PyPulseq Sequence that calculates the sequence into the sampled transmit waveforms. Sequence calculation
    UnrolledSequence The resulting calculated sequence composed of the RF and gradients waveforms and digital control signals. It also includes the RxData templates and the parameters used for the scaling the waveforms. Sequence calculation
    TxCard Sets up the AWG module and streams the sequence waveform to the AWG module. Acquisition
    RxCard Sets up the digitizer and performs the gated recording. Acquisition
    RxData Data of one ADC event containing meta information, processing parameters, the raw samples and the processed data. Postprocessing
    RxProcessor Pool of worker processes that performs the postprocessing during the acquisition. Postprocessing, [5]
    AcquisitionData Result container with the receive data, the sequence, the device configuration and the acquisition parameters. Acquisition, [4]
    spcm_core Low-level Python bindings of the Spectrum driver, provided by Spectrum Instrumentation as a python package. spcm-core
    Spectrum driver Vendor driver library and kernel module to configure the measurement card operations and transfer the data between host memory and the cards. Spectrum Instrumentation download area

    Hardware

    The hardware components mentioned in the diagram above are briefly explained below and summarize a minimal set needed to do MRI. The table lists example components where most of them are open source, which could be used to build a working MRI system.

    Composition of the Hardware

    This documentation focusses on the Nexus console. It does not address the composition of an MRI system. For additional information or documentation about how to build the hardware components listed below visit the OSI² GitLab.

    Component Description Example
    AWG Arbitrary waveform generator. Outputs the RF and gradient waveforms together with the digital control signals for synchronisation and RF unblanking. M2p.5933-x4
    Digitizer Records the MR signal in gates triggered by the AWG. M2p.6546-x4
    Gradient power amplifier (GPA) Converts the gradient waveforms into coil currents. TU Delft GA2
    Gradient coils Generate the gradient fields for spatial encoding. 32cm Gradient Insert
    RF power amplifier (RFPA) Amplifies the RF waveform; enabled by the unblanking signal around each RF pulse. RFPA-Shoebox
    T/R switch Routes the RFPA output to the RF coil during transmission and the coil signal to the preamplifier during reception, protecting the receive chain. Passive TR Switch
    RF coil Antenna handling the transmission of RF energy and the reception of the MR signal (usually we use the same coil for transmit and receive). RF Head Coil
    Preamplifier Low-noise amplification of the MR signal before digitisation. Double Channel Preamp
    Magnet Generates the static field B0, which determines the Larmor frequency (not shown in the figure). 30cm Halbach Magnet
